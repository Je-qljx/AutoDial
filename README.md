# AutoDial — 宽带自动拨号守护脚本

## 摘要

**解决的问题**：宽带网线直连电脑且需要电脑拨号时，每次重连网络（电脑开机或重启时）都需要在设置中手动点击一次“拨号”，操作不便。

**实现方式**：一个开机自动运行的小工具（几个脚本文件，不用安装任何软件），每 15 秒检查一次网络：断线就自动拨号恢复；显示连着却上不了网就自动断开重连。两道保险防止帮倒忙：

- **认得自家的线**：记住自家光猫的特征，网线插到别的网络（公司内网、别人家路由器）时坚决不拨号；这份记忆还会随日常使用自动更新。
- **失败不硬试**：拨号失败会自动拉长重试间隔，不会疯狂重试把宽带账号锁死。

另配一个图形管理窗口：红绿灯显示各项状态，红哪点哪、一键修复——不懂命令行也能装好；搬到新电脑，照着清单把红灯逐个点绿即可。

---

检测到**网线插在指定的宽带光猫链路上**、但**宽带 PPPoE 会话未连接**（或会话僵死无法上网）时，自动拨号恢复宽带。全程只操作「宽带连接」这一个拨号条目，**不改路由、不改网卡设置、不碰 WLAN / 蓝牙 / 其他有线网络**，因此其他网络连接不受任何影响。

**防误拨**：通过「链路指纹」识别网线另一端是不是你的宽带光猫——插了其他网络的网线（公司内网、另一台路由器等）**绝不会触发拨号**，详见下文「链路指纹绑定」。

## 快速开始（命令行）

1. 插好宽带光猫的网线，双击运行（或右键 →「使用 PowerShell 运行」）`Install-AutoDial.ps1`。
   若被执行策略拦截，改用命令行：
   ```
   powershell -NoProfile -ExecutionPolicy Bypass -File "D:\AutoDial\Install-AutoDial.ps1"
   ```
2. 首次安装会自动绑定当前链路指纹，然后注册开机自启并拉起隐藏的守护进程。自启优先用**计划任务**（登录即启动，不用等系统处理启动文件夹，开机后几秒内开始监控）；若系统拒绝注册则回退为启动文件夹快捷方式，安装输出会说明实际用了哪种。

之后每次开机登录都会自动开始守护，无需任何人工干预。


## 链路指纹绑定（防误拨核心）

脚本把光猫在网卡上留下的稳定特征保存到 `gateway.mac`（JSON 格式）作为指纹，包含三部分：

| 特征 | 说明 |
|---|---|
| 设备 MAC 集合 | 从网卡邻居表学到的光猫 MAC，可有多个 |
| IPv6 链路本地地址 | 光猫的 fe80:: 地址（如学到） |
| **网段前缀白名单** | 如 `36.5.`——桥接模式下网卡 IP 由运营商 IP 池分配，**每次插拔网线可能换网段**（36.5.200.x → 36.5.63.x），所以只记运营商大段前缀而非精确网段 |

**自动学习**：每次拨号成功且联网正常时（足以证明是自家线路），脚本自动把当时学到的 MAC/网段前缀并入指纹。运营商调整 IP 池、光猫换 MAC 后无需手动重绑。

每轮拨号前的判定：

| 当前链路状态 | 脚本行为 |
|---|---|
| 学到的设备 MAC 与指纹匹配 | 拨号 ✅ |
| 什么都没学到，但 IP 前缀在白名单内（如 36.5.*） | 拨号 ✅（兜底） |
| 学到了其他设备的 MAC（插了别的网络） | **拒绝拨号** ❌ |
| IP 前缀不在白名单内（其他运营商/内网） | **拒绝拨号** ❌ |
| 无任何可识别特征（空线/未知链路） | **拒绝拨号** ❌ |

相关操作：

```powershell
# 重新绑定指纹（换光猫、换网线插口、搬家后必做）
powershell -NoProfile -ExecutionPolicy Bypass -File "D:\AutoDial\AutoDial.ps1" -BindGateway

# 清除绑定（恢复为不校验指纹）
powershell -NoProfile -ExecutionPolicy Bypass -File "D:\AutoDial\AutoDial.ps1" -ClearGateway
```

绑定在宽带断开时也能完成（MAC + 网段特征不依赖拨号会话）。若运营商把 IP 池换到全新网段（如 36.5. 换成 58.34.），白名单兜底会失效一次——此时只需重新运行一次 `-BindGateway`。

## 工作逻辑（每个检查周期执行一次，默认 15 秒）

1. **网线检测**：指定的有线网卡（默认「以太网」）未插网线 → 本轮直接跳过，什么都不做。
2. **链路指纹校验**：网线在位但指纹不匹配（插在其他网络上）→ 本轮跳过，绝不拨号。
3. **会话检测**：宽带 PPPoE 会话未连接 → 立即拨号（使用系统已保存的宽带账号密码）。
4. **连通性探测**：会话在 → 对 `223.5.5.5 / 119.29.29.29 / 114.114.114.114` 做 TCP 53 探测（IP 直连不依赖 DNS，并尽量绑定宽带出口；三个目标**并行**探测，最坏耗时等于单个目标超时）；任一通即视为正常。
5. **指纹自动学习**：观察到「宽带连接 + 探测正常」时，把当前学到的光猫 MAC/网段前缀并入指纹（覆盖手动拨号、运营商换 IP 池等场景）。
6. **僵死恢复**：会话在但**连续 3 轮**探测全部失败 → 断开会话后重新拨号。

### 拨号双通道

实测部分运营商 PPPoE 服务器对裸 `rasdial`（RasDial API）的认证请求一律拒绝（本机 26 连败），而 UI 路径（RasDialDlg）正常。因此拨号顺序为：

1. **`rasphone -d`（首选）**：与用户在「网络连接」里点连接完全同源，静默拨号
2. **`rasdial`（兜底）**：rasphone 90 秒内未建立会话才启用

### 失败退避

- 普通失败（651 链路未就绪等）：15s 起步指数退避，上限 10 分钟
- 认证类失败（691/628，旧会话占用）：前 6 次每 30 秒紧盯（抓住会话快速释放窗口），之后转 15 分钟长退避防锁号
- 错误 813（连接已在进行中）：等待其完成，超时才断开重拨

## 配置修改

配置优先读 `AutoDial.json`（与脚本同目录）；文件缺失或非法时使用 `AutoDial.ps1` 顶部「配置区」的内置默认值。**换机适配只需改 JSON**，不要动脚本：

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `BroadbandName` | `宽带连接` | PPPoE 拨号条目名，须与「网络连接」里显示的名称一致 |
| `WiredAdapters` | `["以太网"]` | 插网线的物理网卡名，可写多个 |
| `CheckInterval` | `15` | 检查周期（秒） |
| `FastPollIntervalSec` / `FastPollWindowSec` | `5` / `120` | 开机快速轮询：守护启动后前 120 秒用 5 秒节拍（开机初期网络栈未就绪，密节拍尽早捕获就绪时刻），之后回 `CheckInterval` |
| `ProbeIPs` | 阿里/腾讯/114 DNS | 探测目标（TCP 握手判真实连通），海外/企业网络按「特殊网络环境的适配」更换 |
| `ProbePort` / `ProbeTimeoutMs` | `53` / `3000` | 探测端口与单目标超时（毫秒） |
| `FailThreshold` | `3` | 连续几轮探测失败才断开重拨 |
| `BaseBackoffSec` / `MaxBackoffSec` | `15` / `600` | 拨号失败退避基数与上限（秒） |
| `AuthFailBackoffSec` / `AuthFastRetryCount` | `900` / `6` | 认证类失败长退避（秒）/ 紧盯期次数 |
| `LogKeepDays` / `EnableLogFile` | `30` / `true` | 日志保留天数 / 是否写日志文件 |

改完配置后重启守护进程生效：最简单是打开管理界面点「重启守护」；命令行则先运行 `Uninstall-AutoDial.ps1`，再运行 `Install-AutoDial.ps1`。

## 迁移到其他设备

整套方案可以搬到任何 Windows 10/11 机器：所有脚本逻辑通用，无第三方依赖（只用 PowerShell 5.1 和系统内置的 `rasphone`/`rasdial`/`Get-NetAdapter` 等）。机器相关的数据（指纹、日志）不入 git 仓库，新机器上重新生成。目标环境的网络有特殊限制（海外、企业防火墙）时，另见文末「[特殊网络环境的适配](#特殊网络环境的适配)」。

### 迁移步骤

1. **前提确认——目标环境必须是桥接光猫**：PC 能直接 PPPoE 拨号。如果目标环境光猫是路由模式（光猫自己拨号），那台机器本来就不存在「掉线重拨」问题，本方案不适用。
2. **目标机先手动建好拨号**：在 Windows 网络设置里创建 PPPoE 连接，填入宽带账号密码并**连接成功一次**（这一步让系统保存凭据，脚本依赖它；同时确认账号线路本身可用）。这一步是系统操作，无法自动化。
3. **克隆/拷贝本仓库到目标机**（例如 `D:\AutoDial`），**不要携带** `gateway.mac`——里面绑的是旧机器的光猫特征，带过去会挡住拨号。git 拉取天然不带它。
4. **双击 `打开管理界面.vbs`**，按红绿灯清单逐项处理：
   - 「配置文件」红灯 → 点「生成模板」，然后点「配置详情」核对各项含义；`BroadbandName`（目标机拨号条目名，默认「宽带连接」）需手动编辑 JSON 核对，`WiredAdapters` 不用抄名字——「有线网卡」红灯行点「选择网卡」从列表里勾选即可；目标环境在海外或企业网络内的话，同时核对 `ProbeIPs`/`ProbePort`（见「特殊网络环境的适配」），保存后重新检测
   - 「拨号弹窗」红灯 → 点「一键关闭弹窗」（自动把 pbk 的 PreviewUserPw 改为 0 并备份原文件；等价于手动在宽带连接属性里取消「提示名称、密码、证书等」——不关的话 rasphone 拨号会弹凭据框卡住无人值守流程）
   - 「链路指纹」红灯 → 插好宽带网线后点「绑定指纹」
   - 「开机自启」「守护进程」红灯 → 点「安装自启」「启动守护」（或直接点底部「安装并启动」）
5. **验证**：全部绿灯后，拔插一次网线，点「查看全部日志」（滚到最底部）看出现「拨号成功」即闭环。

### 移植性说明

- **指纹自动重建**：管理界面一键采集目标机光猫特征；首次拨号成功后自动学习补全 MAC/网段，无需手工搬数据。
- **无需编译，更新方便**：整套方案是纯 PowerShell 脚本，改代码只需覆盖 `.ps1` 文件，没有打包/编译环节（刻意不做 exe：无签名 exe 会被杀软误报，且每次改动都要重新打包分发）。
- **拨号双通道照样生效**：本机实测的「rasdial 26 连败、UI 路径全胜」是本机运营商的特性；其他运营商可能两者都通（双通道无影响）或都拒（那是线路/账号问题，不是脚本问题）。双通道设计已覆盖各种情况。
- **环境差异已兼容**：`Get-NetAdapter` 状态的数字/字符串枚举、中文网卡名编码（.ps1 已带 BOM）、DHCP 动态网段等环境差异，脚本内部已做兼容，不需要按机器改逻辑。
- **断开后的会话释放窗口**（约 1~3 分钟，部分运营商更长）由运营商侧决定，任何机器都绕不开；脚本紧盯期会自动抓住释放时机。

### 特殊网络环境的适配

默认配置面向中国大陆家用宽带。目标环境不同时改 `AutoDial.json` 即可适配，无需动脚本：

- **海外网络**：默认探测目标（223.5.5.5 等国内公共 DNS）可能延迟高或不可达——正常连接会被连续误判为僵死，触发无谓的断开重拨循环。把 `ProbeIPs` 换成本地可达的公共目标（如 `["1.1.1.1", "8.8.8.8"]`）。
- **企业/受限网络**：部分防火墙禁止对外 TCP 53。把 `ProbePort` 换成放行的端口（如 80/443）；探测是 TCP 握手，目标 IP 需在该端口提供 TCP 服务（大厂 DNS 与 CDN IP 通常可用）。
- **换完先验证再上线**：`powershell -c "Test-NetConnection <探测IP> -Port <端口>"` 能通，再改 JSON 重启守护；否则误判循环会出现「宽带已连接」后紧接「连续 N 轮探测失败→断开重拨」的日志模式，据此也容易定位是探测目标的问题。
- **WSH 被禁用的环境**（部分企业策略整体禁用 wscript）：两个 `.vbs` 入口会失效。把计划任务/快捷方式直接指向 `powershell.exe -NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -File AutoDial.ps1 -Detached` 即可绕开。
- **多用户共用电脑**：守护跟随安装它的用户运行（计划任务按用户登录触发），而宽带账号是全局唯一的——第二个用户不要重复安装，否则两个守护会抢占同一个 PPPoE 会话（后拨的报 691）。
- **Windows 版本下限**：Win10/11（系统自带 PowerShell 5.1）。Win7 默认只有 2.0（缺 `ConvertFrom-Json`），除非先补装 5.1。

## 常见拨号错误码

| 错误码 | 含义 | 处理建议 |
|---|---|---|
| 691 | 账号密码错误 / **账号已被其他会话占用** / 欠费停机 | 确认光猫不是路由模式（内置拨号会占用账号）；确认宽带未欠费；重启光猫释放会话 |
| 651 | 调制解调器（或远程服务器）报错 | 检查光猫/线路，通常需重启光猫或报修运营商 |
| 678 | 服务器无响应 | 多为运营商侧或线路问题，重启光猫 |
| 628 | 连接完成前被远端终止 | 两种可能：①会话刚断开未释放（几分钟内自动恢复）②**认证被拒**（rasdial 常把 691 报成 628）。脚本通过系统认证事件日志区分，认证类失败自动改用 15 分钟长退避 |
| 813 | 连接已在进行中 | 脚本已自动处理（等待其完成，超时才断开重拨） |
| 619 | 端口断开 | 稍等自动重试；频繁出现则检查线路 |

**628 持续超过 30 分钟的处理**（日志中出现「认证类失败」提示时）：
1. 确认光猫是桥接模式（路由模式的内置 PPPoE 会占用账号，本机再拨就报 691/628）
2. 重启光猫（释放运营商侧旧会话）
3. 若仍不行，联系运营商报「账号被占用」，要求强制下线

脚本遇到这些错误不会疯狂重试（普通失败指数退避，认证类失败 15 分钟一次），恢复线路后下一轮会自动拨通。

## 卸载

打开管理界面点「停止并卸载」，或运行 `Uninstall-AutoDial.ps1`：删除开机自启并结束守护进程。宽带连接的当前状态不会被改动。

## 常见问题

- **为什么守护进程可能检测不到我插网线？** `AutoDial.json` 里 `WiredAdapters` 的网卡名必须与「网络连接」（ncpa.cpl）里显示的名称完全一致。
- **插了其他网络的网线会误拨号吗？** 不会。链路指纹不匹配时脚本直接拒绝拨号（日志里会记「链路指纹不匹配…禁止拨号」）。前提是完成过 `-BindGateway` 绑定。
- **什么时候需要重新绑定指纹？** 更换光猫、光猫更换了 LAN 口（MAC 不会变，一般无需重绑）、搬家换线后运行一次 `-BindGateway` 即可。
- **守护进程会不会重复拨号？** 不会。脚本用互斥锁保证同一用户下只有一个实例；重复运行安装脚本也只会激活已有的实例。
- **WLAN / 其他网络会被影响吗？** 不会。脚本只调用 `rasdial` 操作宽带条目，加上只读的网卡查询与 TCP 探测，不修改任何路由、网卡 metric 或其他适配器。
